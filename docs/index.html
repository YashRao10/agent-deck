Multi-Agent Command Deck

MACD

A terminal multiplexer and orchestration layer for running a fleet of Claude Code sessions as coordinated workers. Split panes watch several agents at once, and a message/task router underneath lets one session delegate work to others and track what came back.

What it does

Split-pane TUI

Spawns real claude processes via node-pty and renders them side-by-side with ink — watch a whole fleet at once, not one session at a time.

Cross-process messaging

macd send routes a message from any terminal into a live pane over a real socket (a named pipe on Windows), so orchestration isn't confined to one process.

Task tracking

macd assign / tasks / task-status track work through pending → in progress → done/failed, persisted across processes and sessions.

Live status, not just logs

A spawned pane's crash is distinguished from a clean shutdown in real time — the registry reflects what actually happened, not a uniform "offline."

Architecture

Orchestration coreregistry · router · CLI — no native deps
↕ implements Transport
PTY / multi-pane UI layernode-pty · ink — verified on macOS and Windows

This project is its own dogfood case — built across two real machines, a Windows session acting as orchestrator and a MacBook session acting as a worker, using exactly the kind of cross-session delegation MACD is meant to formalize and visualize.

Get started

# clone and build
git clone https://github.com/YashRao10/macd.git
cd macd
npm install
npm run build

# spawn two live sessions, side by side
node dist/cli.js watch worker-1 worker-2

# from a second terminal
node dist/cli.js send worker-1 "check CI"

# read-only web view at http://127.0.0.1:4317
node dist/cli.js dashboard
